# 分集视频提示词（step_3）

按集生成，用户也可以指定只做某一集。**版本由「分镜管理 → 全局配置 → 剧本转视频提示词」决定，不要再问用户选哪一版。** Host 会在本技能末尾追加当前选中的权威提示词文件；开工前必须用文件工具完整读取那个文件，并以它为唯一依据。

| 版本 | 说明 | 权威提示词 |
|---|---|---|
| **通用小白版**（默认） | 结构稳妥、易读，适合大多数短剧 | `references/PROMPT-通用小白版.md` |
| **自定义** | 用户上传的 txt / md / Word 文档 | 以 Host 追加的文件路径为准 |

所有专业版提示词都不随插件内置或分发。需要使用时，到全局配置上传用户自己保存的文件作为自定义提示词；不要在插件目录里恢复内置副本。

开始前用文件工具**完整读一遍 Host 指定的那份提示词全文**，然后严格按它执行；不同版本的结构、字段名、硬性规则不得混用或改写。用户要换版本时，让他到全局配置切换，不要在本步骤临时改口径。如果用户上传的自定义版本使用 `【大分镜N】` 和 `【取景机位】/【画面内容】/【环境音】/【台词】/【画风锁定】`，Host 的 H3 转换会按这组字段适配，不能把它们改回标准版字段。

所有版本共同的底线（以所选版本的规定为准，冲突时以版本文件为准）：

- 输入是**本集剧本**和**场景图**。本集剧本开头前 3 段必须已经写明本集出场人物、场景、道具；这三段中的资产名就是资产映射的唯一来源，原样照写，不加前缀、不加编号、不带后缀。
- **台词完整性是最高优先级**：剧本里每一句台词（含 O.S. 画外音与内心 OS）都要逐字完整出现在对应分镜里，不得遗漏、删减、概括、合并或自创。
- 场景图是空间、站位、光源方向的唯一依据，不允许凭文字脑补空间。
- 台词出现顺序、每句归谁说、口型一致，都不能错。
- 无台词分镜末尾写"无台词，只有呼吸与眼神变化"；画面里没有人物时写"无台词，无人物"。
- 时长必须写具体数字和"秒"，不写区间、不写"约"。
- **每个大分镜都自带本段的映射，一个都不能省。** 每个 `【大分镜N】` 内部都必须有它自己的【人物映射】【场景映射】【道具映射】，只列**这一段**出场的人物、用到的场景和道具，`@` 只写在这一节里。**不要**在文件开头写一份"整集资产映射"然后在各段里省略——那样每段单独复制出去时，人物和道具就没有绑定了（`storyboard action=health` 会把这种文件点名报出来）。
- **视频提示词的映射栏只允许选资产库已有资产。** 人物、场景、道具三个按钮分别只列资产库里的 `character` / `scene` / `prop`，不能从这三个入口本地上传新文件。只有【其他参考图片映射】【参考音频映射】【参考视频映射】提供本地上传。选择后必须把对应 `@名字` 行写进本大分镜自己的映射节，不能只把裸 `@` 追加到正文末尾。
- **映射里的变体必须已经有合法来源。** 场景夜版、人物服装/年龄/受伤/形态变体、道具状态变体，都只能由原资产通过 `task=image-edit` 得到；不能因为提示词里写了这个变体，就用文生图新造一张。资产库里没有对应变体时，先回到资产生成阶段补齐，不能拿基础图冒充变体，也不能用文字描述代替图片绑定。
- **本大分镜映射节里的显式选择是用户决定，不能被转 H3 时当成“正文没再写一遍”而丢掉。** 尤其是【其他参考图片映射】里的站位图、构图图、关键帧或其他作用图，即使正文没有第二次手打 `@名字`，转 H3 也必须保留为一个独立 `<Picture N>`，并按用户写的用途短语解释。`初始站位参考@文件`、`构图参考@文件` 这类写法必须识别，H3 里不能拿上传文件名冒充资产名。删除只能由用户删掉映射行或对应的功能参考句来触发。
- **编辑器里的 `@` 候选只来自当前大分镜左侧资产栏，并按左侧一张卡对应一条候选。** 已在本块绑定的人物、场景、道具、其他参考图片、参考音频和参考视频都可以插入；不要把同一人物的其他服装/状态变体自动展开。项目库的其他资产、已经删除的旧音频不得混入。要新增引用，先在左侧资产栏选择或上传，再在提示词里用 `@`。
- **左侧资产栏和视频提示词正文是两套状态。** 改动正文、删掉句子或删掉 `@名字`，都不能删除左侧已选资产；只有点击素材卡上的 `×` 才是显式移除。正文里的 `@` 负责新增和关联，不负责清空素材栏。
- 人物卡片里上传的自带音色会作为当前块的一条音频资产出现在左侧，并以 `@角色名（音色）` 插入。这个写法直接绑定该人物的 `role: voice` 文件，不会把它误当成名为“音色”的服装变体。
- **小道具不占参考槽，写进【画面】。** 参考槽是稀缺资源（H3 最多 9 张图、3 段音频、3 段视频，且开一张图就要多算一遍 2048px 的参考编码，直接拖慢生成）。所以只有**承载剧情或身份识别**的道具才进【道具映射】并 `@`：合同、照片、信件、手机屏幕、信物、武器这类"观众要看清它是什么"的东西。**竹凳、花生、碗筷、纸箱、水杯、纸巾、工具、地上的碎石**这类随手物，一律作为场景内元素写进【画面】（写清外观、位置、被谁拿起放下），**不进映射、不占槽**。判断标准一句话：**删掉它剧情会断吗？会 → 进映射；不会 → 写进画面。**
- **格式以 `测试短剧` 项目里那份为准**，每段长这样（顺序固定，不要加别的标题）：

  ```
  【大分镜1】
  【画面风格和类型】电影级写实画面，注重光影氛围与细节，质感逼真。
  【人物映射】
  陈默（形象及服装参考: @陈默）
  【场景映射】
  旧书店内景（场景画面布置参考： @旧书店内景 夜/内景）
  【道具映射】
  借书卡（道具外观参考： @借书卡）
  【初始站位】
  陈默 站在 旧书店内景 画面中心偏左的书架前，…
  【分镜1】（时长：3秒）
  【摄像机景别】中景，平拍，右侧面，固定机位
  【拍摄主体】陈默
  【画面】…
  ```

  大分镜之间用 `---` 分隔。**不要**写 `# 第N集 - 大分镜N`、`### 大分镜N（总时长…）` 这类标题——文件名已经说明了是哪一个，标题只是把正文往下推。
- 按用户指定格式交付，不附加自检表或自检章节。
- **改提示词时，改的不是一处。** 同一条指令在这里会被写进好几个字段：`【画面】` 里有，`summary` / `detailed_description` / `overall_soundscape` 里往往又复述了一遍（H3 的每个字段都是独立读进去的，模型不会替你合并）。实测：只改了 Shot 描述里的"不要画外音"，`summary` 里残留的那句仍被当成指令执行，画外音照样出来了。
  所以用户提出修改后，**先把要改的关键词在全文里搜一遍**（画外音 / 台词 / 人数 / 服装 / 道具名 / 时长 / 镜头方向…），逐个字段改到一致再交付。交付说明里写清"改了哪几处"。若正文使用了 `h3-prompt-writing` 的六字段结构，也要同步检查；但这些字段不是生成前置条件。

交付：存成 `剧集/第N集/第N集视频提示词.txt`（用户可指定别的名字），并告诉用户"这个文件你可以随时直接改，改完我用改后的版本继续转 H3"。

**生成完成后先让模型分配分镜块。** 调用 `storyboard action=model-parse project=<项目> episodeNumber=<集数> file=<本集视频提示词> task=split`，由当前会话模型完整读取视频提示词，再按剧情节点、1–4 个镜头/块、每块不超过 15 秒重新划分 `【大分镜N】`。不要因为用户选择的提示词模板没有要求 `【大分镜N】`，就让代码把整集当成一个块；模型负责分配，代码只负责校验和落盘。分块完成后再逐块转 H3。
