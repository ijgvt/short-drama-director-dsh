## 一、和旧工作流的三处本质差别

| | 旧工作流（多参考生视频-优化版） | **新工作流（终极篇-文武双全）** |
|---|---|---|
| 生成模式 | **两种模式**（一采抽卡 / 二采） | **只有一种：一采 + 二采，直出二采** |
| 抽卡 | 有一采抽卡环节 | **没有抽卡**，一采直接进二采 |
| 尺寸 | 节点上写死 1344×768 | **分辨率选择器**动态算，宽高是链路输入 |

**"直出二采"的含义**：一采在低分辨率上试，二采在放大后精修，**最后的产物就是二采的结果**。所以不存在"抽卡选一张再放大"这一步——一次提交就是成片。

## 二、你要灵活修改的四个参数

### 2.1 分辨率 —— `ResolutionSelector#252`

```
widgets: ["16:9 (Widescreen)", 1.5, 32]
          ↑ aspect_ratio      ↑ megapixels ↑ multiple
```
- `width` / `height` 两个输出 → `MiniMaxH3ReferenceToVideo#265`
- 它是**内置节点**（`comfy_extras.nodes_resolution`），不是插件

**megapixels 对照表**（工作流作者写在 `MarkdownNote#248` 里，我原样转录）：

| megapixels | Aspect | 输出（multiple=32） |
|---|---|---|
| 0.2 | 16:9 | 608 × 352 |
| 0.3 | 16:9 | 736 × 416 |
| 0.4 | 16:9 | 864 × 480 |
| 0.5 | 16:9 | 960 × 544 |
| 0.6 | 16:9 | 1056 × 608 |
| 0.7 | 16:9 | 1152 × 640 |
| 0.8 | 16:9 | 1216 × 672 |
| 0.9 | 16:9 | 1280 × 736 |
| 0.98 | 16:9 | **1344 × 768**（等于旧工作流的写死值） |
| 1.0 | 16:9 | 1376 × 768 |
| 1.2 | 16:9 | 1504 × 832 |
| **1.5** | 16:9 | **1664 × 928**（当前值） |
| 1.8 | 16:9 | 1824 × 1024 |
| 2.0 | 16:9 | **1920 × 1088** |

竖屏短剧要换成 9:16 那一档；**比例和像素数都要按用途挑，不要照抄当前值**。

### 2.2 视频时长 —— `PrimitiveFloat#259`（标题：视频时长（秒））

```
widgets: [10]     ← 当前 10 秒
↓
ComfyMathExpression#250
表达式: max(5, round(a * 24)) + (5 - (max(5, round(a * 24)) % 17)) % 17
↓ INT → MiniMaxH3ReferenceToVideo#265.length
```

**这个表达式在干什么**（要理解才能灵活改）：
1. `round(a * 24)` —— 秒数按 **24 fps** 换成帧数
2. `max(5, …)` —— 下限 5 帧
3. 后面那一串把帧数**向上凑到 `(17n + 5)` 的形态**

为什么必须凑：`MiniMaxH3ReferenceToVideo.length` 的定义是 **range 5~3600, step 17**。**直接给 240（10 秒 × 24）会被拒或行为未定义**，所以时长只能通过这个表达式走。

> **改时长就改 `#259` 的 value，不要改 `#250` 的表达式。** 表达式是适配器的安全网。

**实测印证**：工作流自己保存的上一次产物是 `duration 13.667s / frame_count 328`，`328 = 17×19 + 5` ✓。

### 2.3 基础调度器是**总步数** —— `BasicScheduler#261`

```
widgets: ["beta", 10, 1]
          ↑scheduler ↑steps ↑denoise
```
- `steps = 10` 是**一采 + 二采的总步数**
- 输出 `SIGMAS` → `SelfLiftH3Sampler#397.sigmas`

### 2.4 transition_step 是**一采步数** —— `SelfLiftH3Sampler#397`

把这个节点的 widgets 按真实字段名拆开（顺序来自 `/object_info`）：

| 字段 | 当前值 | 含义 |
|---|---|---|
| `seed` | 235588422702935 | 种子 |
| （control_after_generate） | `randomize` | 每次随机 |
| `cfg` | 1 | |
| **`transition_step`** | **6** | **一采步数**（在总步数里切分） |
| `lowres_scale` | 0.6 | 一采的低分辨率缩放 |
| `rho` | 0 | |
| `w_min` | 0.5 | |
| `w_max` | 1 | |
| `upscaler_model` | `h3_upscaler_lms_v0.1.safetensors` | 二采用的放大模型 |
| `highres_tiling` | true | |
| `upscaler_unload` | true | |

**两个步数的关系**：`基础调度器.steps = 10`（总），`transition_step = 6`（一采）。
即 **一采跑 6 步、二采接着跑剩下的 4 步**。调这两个数字时要保持 `transition_step < steps`，否则二采没有步数可分。

节点全名：**`SelfLiftH3Sampler`**（"SelfLift Progressive Sampler (MiniMax H3)"），来自 `custom_nodes/comfyui-SelfLift`。
上游：`model` ← `GetNode#251`，`sampler` ← `KSamplerSelect#255`（`euler`），`vae` ← `GetNode#327`。
下游：`LATENT` → `VAEDecode#253` + `VAEDecodeAudio#254`。

## 三、参考素材：上限是硬的

工作流作者的三条 Note 原话（`#59` / `#24` / `#46`）：

| 约束 | 值 |
|---|---|
| **所有素材（图 + 视频 + 音频）混合总数** | **不超过 12 个** |
| 参考图像 | **最多 9 张**；不接入的**用开关关掉** |
| 参考视频 | 最多 3 段，**每段 2–15 秒**，总时长 ≤ 15 秒 |
| 参考音频 | 最多 3 段，**需与图像或视频搭配**，总时长 ≤ 15 秒 |

### 参考图上传目标

对应的 `LoadImage` 节点（**上传图就是往这些节点传**）：

|---|---|---|---|
| `#49` | **0 启用** | `男患者角色设定图2.jpg` | |
| `#50` | **0 启用** | `首帧场景4.jpg` | |
| `#51` | **0 启用** | `女医生角色设定图.jpg` | |
| `#19/#23/#199/#200/#201/#43` | **4 旁路** | `None` | 备用槽位，用之前**必须在 ComfyUI 界面取消旁路并保存** |

> ⚠️ **旁路（mode=4）的槽位不会被算作可用容量**。本插件按**实际接线**统计参考槽位（`slots.counted-from-wiring`），所以往一个旁路节点传图会被预检拦下——这是对的，因为上传进去也不会参与生成。

### 虚拟连线：LoadImage → SetNode → GetNode

这份工作流**不使用直接连线**，而是：

```
LoadImage#49 ──IMAGE──> SetNode#6 ("图像…")
                              ↑ 按名字取
GetNode#242 ──────────────> MiniMaxH3ReferenceToVideo#265.ref_images.ref_image_N
```

`GetNode`/`SetNode` 共 **24 + 22 = 46 个**。它们靠**名字**配对，不是靠连线。
**改这份工作流时不要动名字**，改错一个名字会让整条参考链静默失效。

## 六、操作要点（这份工作流特有的）

1. **用之前先取消旁路**：只有 `#49/#50/#51` 三个 LoadImage 是启用的。要用更多参考图，在界面里把备用槽位取消旁路 + 选图 + 保存，否则插件看到的可用槽位只有 3 个。
2. **不要动 GetNode/SetNode 的名字**（第 3 节）。
3. **时长只改 `#259`**，别改 `#250` 的表达式。
4. **`length` 必须是 `17n+5`**，由表达式保证；手工改 `#265.length` 会破坏它。
5. **素材总数 ≤ 12**，其中图 ≤ 9。
6. **画面比例要按用途挑**（短剧通常 9:16，不是当前的 16:9）。
