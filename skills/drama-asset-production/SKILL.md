# 资产生成（step_2）

输入是《资产提示词》与当前可用的 ComfyUI 实例。运行端和工作流**一律以全局配置为准**：文生图、图片编辑、图像超分、视频超分、视频生成分别读取各自保存的本地/云端选择与工作流。只有用户当场明确要求换一份工作流或换运行端时才覆盖；不要按文件名猜默认值。确认模式仍按下面的半自动 / 全自动 / 手动执行。

## 资产变体来源硬闸门（最高优先级）

**文生图只允许创建第一次出现的原资产；任何已有资产的变体只能由原资产通过图像编辑工作流得到。**

| 请求 | 允许的任务 | 不允许的任务 |
|---|---|---|
| 人物第一次出现的基础定妆照 | `task=text-to-image` | — |
| 人物换装、年龄、受伤、战损、妆造等变体 | `task=image-edit`，以该人物原定妆照/原变体为 `images.image_1` | `task=text-to-image` |
| 场景第一次出现的基础空镜 | `task=text-to-image` | — |
| 场景日→夜、夜→日、雨天、反打、改造前后 | `task=image-edit`，以同一场景原图为 `images.image_1` | `task=text-to-image` |
| 道具第一次出现的基础图 | `task=text-to-image` | — |
| 道具开合、损坏、发光、纸化等状态 | `task=image-edit`，以该道具原图为 `images.image_1` | `task=text-to-image` |

提交前必须确认：**任务名是 `image-edit`，第一张源图是原资产的真实文件版本，输出登记在原资产的变体下。** 找不到原资产时停下来让用户确认，不能凭文字脑补一个“差不多”的变体。发现某张图实际是文生图产物却放在变体目录里，不得继续同步到集或作为后续参考；从原资产重新编辑后再登记，并在交付里写明纠正。

场景日夜变体尤其不能只因为提示词写了“夜景”就重新文生图；必须从同一场景的已有图编辑，保留空间、陈设、门窗和机位关系，只改变光源、色温、明暗和时间氛围。人物服装变体尤其不能先用文生图生成“服装参考图”；新服装直接写成图片编辑指令，用户提供的外部服装图只能作为第二张参考，人物身份始终来自第一张原定妆照。

## 生成顺序与确认模式

- 顺序：用户指定的先做；没指定就**人物 → 场景 → 道具**，同类内按出场顺序。
- 半自动（默认）：主要角色（男主、女主、男二、女二）的**定妆照**要用户确认后才做四视图；**场景图**要用户确认后才超分。其余全自动。
- 全自动：不停下来确认，一路生成到底。
- 手动：每一步（定妆照、四视图、超分、换装）都先给用户看，确认才继续。
- 需要确认的图**必须发到聊天窗口**：用 `read_image` 读那个文件，并写一句"这是 X 的定妆照，确认后我做四视图"。用户不满意 → 按他的意见改提示词重出，不要让他自己改文件。

## 工具用法（先看再跑）

1. `comfy_graph` 读工作流，拿到**节点号与输入名**。不要凭记忆写节点号——这些工作流被反复保存过，节点号会变。
2. `comfy_run` 出图：**传 `task`，不要传 `workflow`**。任务映射固定为 `text-to-image`（文生图/定妆照）、`image-edit`（换装/场景改夜/图生图）、`upscale-image`（图像超分）。Host 会按全局配置解析本地/云端运行端和实际工作流。`patch` 按 `"<节点号>.<输入名>"` 改，`inputs` 按 `"<LoadImage 节点号>": "本地图片路径"` 上传参考图，`output` 指定存到哪个资产文件夹，`copy_as` 把产物重命名成资产名。
3. 跑得久就用 `comfy_job` 跟进（同一 `prompt_id`）。
4. **输入被链接占用的坑**：一个输入如果已经接了别的节点（例如 `KSampler.seed` 接了 `Seed (rgthree)`），直接 patch 它无效——要改的是**上游那个节点的值**。`comfy_graph` 里显示成 `<- node N` 的就是链接，顺着往上找。
5. **patch 必须打中真节点**。`comfy_run` 会在以下情况直接报错、不给你假成功：patch 的节点号不存在、图被 ComfyUI 拒绝（`node_errors`）、跑完却一个文件都没产出。看到这些报错先回 `comfy_graph` 对**全局配置实际解析出来的那份工作流**，别当成"生成失败"重试，也不要为了绕过错误改传固定文件名。

## 图像编辑：走全局配置的 Qwen 2.1 编辑流，并按需开启图像槽位

- **只要一次生成要喂 2 张以上参考图**（换装、场景改夜、道具改形态、把 A 的姿势套到 B 上、两个角色同框比比例），就用 `task=image-edit`，运行全局配置里保存的图片编辑工作流。不要用文生图硬拼，也不要分两次生成再拼图。
- 调 `comfy_run task=image-edit` 时默认传 `promptMode: "qwen-official"`，由当前会话模型读取按顺序绑定的全部参考图，把“改什么、每张图各提供什么”改写成 Qwen Image 2.1 官方 Edit Prompt。模型看图核对内容与图片角色，禁止只凭文件名猜图；任何图片读取、模型调用或校验失败都禁止提交。只有用户已经提供可直接运行的千问官方提示词、并明确要求原样提交时，才传 `promptMode: "raw"`；raw 不会替你补编号、画幅或保真条款。
- **先按本次实际参考图数量对槽位，再提交。** 设本次真正需要的不同图片文件数为 `N`。跨机器不得依赖固定节点号、固定 `LoadImage` id 或只看某个旧组名，必须从**当前全局配置实际解析出的工作流**读取。
- 用 `comfy_graph` 找到当前 active 的 `TextEncodeQwenImage21`，列出它现有的 `images.image_1...image_N`。每个槽位向上追踪到实际提供图片的 `LoadImage`；`skipped` 中出现、或保存状态为 `mode=4` / `mode=2` 的节点不算可用槽位。
- **槽位不足时**：找到缺失的 `images.image_K` 对应的上游 `LoadImage` 和图片缩放链，启用这一整组（节点 `mode: 0`）。组标题可能是 `image-K`，也可能被用户改过；标题不同就按槽位编号和上游连线找组，不要按固定标题瞎猜。启用后重新 `comfy_graph`，确认该槽位已经出现在 active 图里。
- **槽位过多时**：把 `image_(N+1)` 之后的对应组设为旁路（`mode: 4`），不要删除节点、不要 mute。关闭后还要确认最终 active 的 `TextEncodeQwenImage21` 只保留 `images.image_1...image_N`，避免旧参考图残留在条件里。
- 在 ComfyUI 界面的操作是：右键对应组标题，把组内节点设为启用或旁路；也可以使用 `Fast Groups Bypasser` 批量切换。单个节点时启用是 `mode=0`，旁路是 `mode=4`。改完必须保存工作流。
- 如果 `comfy_graph` 看不出组标题或组范围，就用文件工具把当前工作流 JSON 当**结构化 JSON**读取：`groups` 提供组标题和 `bounding`，`nodes` 提供节点位置与当前 `mode`；按节点是否位于组矩形内建立组→节点映射。不要用字符串替换，不要猜固定节点号。允许写文件时，先备份，只改目标组的 `mode`（`0` 或 `4`），保留所有 links、widgets 和其他节点字段；没有安全写权限就停下来让用户在 ComfyUI 里改并保存。
- **短剧导演直接调用 `comfy_run task=image-edit` 不会替你自动开关组。** 分镜管理里的通用图像编辑表单会按文件数自动开关，但导演直接调用必须自己完成上面的检查。若当前环境没有写工作流或切组的权限，就停下来，把需要启用/旁路的槽位和组名明确告诉用户，等用户保存后再继续。**绝不把第二张参考图降级成文字，也绝不带着多余旧图开跑。**
- 提示词里写清 `<image1>` / `<image2>` 分别是什么（例如 `把<image1>中人物穿着的【原服装】，整体替换为<image2>中的【新服装】`），不写清楚模型会自己挑。
- **只开真正用到的槽位**：空槽位或多喂一张无关参考图，模型会把它当条件，出图混进不相关的东西。四视图必须只保留 `images.image_1`。
- 提交前必须重新执行一次 `comfy_graph`，验证 active 图同时满足：`N` 个参考槽位都存在、每个槽位都连到正确的 `LoadImage`、没有多余的 `images.image_K`。只有这一步通过后才调用 `comfy_run`。
- 单图从无到有仍然用 `task=text-to-image`（定妆照、场景空镜、道具）；从现有图继续改则用 `task=image-edit`。两者的具体工作流都以全局配置为准。

## 种子：每次都要显式写，否则"重跑一次"等于没跑

实测：同一条提示词连跑两次，两张图**像素级相同**。原因不在提示词，在于种子没写——`Seed (rgthree)` 节点的默认值恒为 `0`，不传就一直是那张图。

- **每次提交都显式给种子**，默认随机（`Math.floor(Math.random()*2**31)`）；用户点名要某张的效果时才固定，并把那个数字记下来。
- 种子一般**不在采样器上**：本机实测 Krea2 文生图的 `7 KSampler.seed` 接的是 `8 Seed (rgthree)`，要写的是 `8.seed`；千问 2.1 编辑/生图流的种子在 `502.seed`。**这两个数字只对本机有效**，换了机器必须先 `comfy_graph` 找；看到输入显示成 `<- node N` 就改上游那个节点（见上面第 4 条）。
- 判据：同一提示词两次出图**像素级一样** = 种子没进去（或写进了被旁路的节点）。这种时候改提示词是白费力气，先把种子打通。
- 用户说"再来一张不一样的"——换种子就够，不用他重写提示词。

## 历史节点示例（不能用于选择工作流）

- `▶▷Krea2-文生图.json`：`4 PrimitiveStringMultiline`（提示词正文，**文字从这里进**）→ `5 CLIPTextEncode`；`9 EmptyLatentImage` 的 `width`/`height` 走 `10 ResolutionSelector`；`7 KSampler` 的 `seed` 接 `8 Seed (rgthree)`。**要改尺寸就改 `10`，要改文字就改 `4`。**
- `▶▷Qwen-image21-图像编辑+生图流（整合）.json`：入口提示词是 `571 PrimitiveStringMultiline.value`；参考图 `475 LoadImage` → `532 ImageScaleToTotalPixels` → `497.images.image_1`；`482 ComfySwitchNode` 的 `on_false` 接 `497` 的参考图尺寸画布、`on_true` 接由 `ResolutionSelector` 控制的空潜变量。同比例换装走参考图尺寸分支；四视图从 9:16 变 16:9，走指定比例分支（当前为 `true`），不要硬编码成单一值。
- 图像超分用独立的 `▶▷VOSR2-图像放大.json`（源图倍数 2x / 3x / 4x）。
- 视频超分用独立的 `▶▷VOSR2-视频放大.json`。工作流先按目标长边预缩放，再由 `TESpeedVOSR2Video` 做 2 倍细化；面板传 `targetResolution=480p / 720p / 1080p / 2K / 4K`，不再传视频 `scale`。

**这些数字和文件名只是历史现场记录，随时会变；实际生成只传 `task`，工作流由全局配置决定，节点号必须先对全局配置实际解析出的那份工作流跑 `comfy_graph`。**

## 人物资产链路

> **不是所有"角色"都能走四视图。** 四视图模板写死了「头肩特写 / 服装 / 头身比」这三条**人形**约束。兽形、器物、机械、灵体本体、以及群体资产（群演）照套，模型会硬长出人脸或人形身体（实测兽形角色被套成"人身兽头"，整张作废）。这类资产档一手：**只出定妆照**（9:16；群像 16:9），需要别的角度就单独再生成一张，**不要**套四视图模板、也不要超分后当四视图登记。
>
> **变体"做完"的标准是它有自己的一套图，不是只有一张定妆照。** 新增造型 / 换装出一个变体后，**不等用户提醒**，立刻对该变体走「9:16 定妆照 → 16:9 四视图 → 3x 超分」并登记。四视图是视频模型真正喂进去的那张：缺了它，这一集引用这个造型时只能退回基础造型（画面上直接穿错衣服）。`storyboard action=health` 会把这类变体点名报出来（`variant-missing-quadview`）。**只有次要角色与群像可以只留定妆照。**

1. **9:16 全身定妆照** — `task=text-to-image`，工作流由全局配置解析。按实际图里的提示词节点和分辨率节点写提示词、设 9:16。纯白底、单人、正面全身、中性表情。
2. **16:9 四视图** — `task=image-edit`，用 `四视图.txt`。要点见 `costume-and-quadview` 技能（提示词写进当前启用的文本节点、当前启用的 `LoadImage` 传定妆照、断开额外图片槽、`ComfySwitchNode` 选由 `ResolutionSelector` 控制的空潜变量分支、`ResolutionSelector=16:9 + 1.5MP`、面部特写的三条硬约束）。
3. **超分到原来的 3 倍** — `task=upscale-image`，工作流由全局配置解析。先 `comfy_graph` 读运行时实际生效的图像放大器和倍数输入，不要凭记忆写节点号。
4. **换装变体**（有需求时）— **直接从该人物原定妆照走 `task=image-edit` + `换装.txt`**，把新服装的颜色、单品、材质和关键细节写进编辑指令；不得先用 `task=text-to-image` 生成服装参考图。用户提供外部服装参考图时，只能把它作为第二张参考，第一张仍必须是人物原定妆照。然后必须重做第 2、3 步。铁律见 `costume-and-quadview`：**必须写原服装**、**不能出现"四个视图/四格"**。
5. **落盘并登记（两步都做，缺一不可）**：存到 `资产/人物资产/<角色名（身份）>/`，文件名就是资产名（变体写 `角色名（造型）`）。再用 `drama_workspace` `action=sync_asset`（`asset_kind=人物`）复制进每一集的 `本集所需资产/`。`asset_name` 必须写完整变体名；dataset 要 `角色名（造型）` 时不能拿基础角色去同步，Host 会按 sha256 判断是否同文件并拒绝缺失变体。

   **登记是必须步骤，不是可选项**：文件落在磁盘上≠资产页里有了。每生成一张（定妆照 / 四视图 / 超分 / 换装变体），都要让它在**资产页**里挂到正确的资产和变体下面：

   - 走 `storyboard action=assets` 的 `assetAction=import`（或面板的上传/替换），`variantName` 写**变体名**（`家居服` / `金` / `锈断`），不要靠文件名猜
   - 然后 `assetAction=refresh` 重扫，并核对：资产页该资产下**这一套图片有缩略图**、变体下拉里能看到它
   - **一条资产一个名字**：不要同名再立一条（`12. 穆昭仙剑`、`穆昭仙剑（金）` 各成一条 = 混乱的根源）；变体走 `variantName`，不是新资产
   - **括号只属于人物变体**：`角色名（造型）` 是契约认的变体写法，人物必须这样写。**场景、道具、群演的资产名里一律不许出现括号**——资产库会把文件名里的第一个 `（…）` 当成变体（`青岚宗弟子（群像）.png` → 资产 `青岚宗弟子` + 变体 `群像`），于是 `@青岚宗弟子` 绑到的不一定是你要的那张，实测抓成了别的群像。群像直接写 `青岚宗弟子群像`，或者只用一个 `青岚宗弟子`。同一件道具要两种形态，就**另起一个独立名字**（`问雪剑` / `问雪剑纸化`），不要写 `问雪剑（纸化）`
   - 生成完就登记，**不要攒到最后**——先做人物再做道具时最容易漏，漏了在面板上就是"有名字没图"
   - 报告里要写清：这次生成了几张、分别登记到哪个资产的哪个变体；**没登记的图不算完成**

### 资产页中的定妆照与一键四视图

- **人物的定妆照就是变体当前形象**：`front` 和旧版 `primary` 都可以作为定妆照输入，不要求用户为同一个变体再上传第二张“定妆照”。
- 换装变体先新增变体，再上传/生成该造型的定妆照；不需要覆盖基础造型。
- 定妆照存在时，点「生成四视图并 3x 超分」会先使用全局配置的图片编辑工作流，按 `costume-and-quadview/references/四视图.txt` 生成 16:9 四视图，再按**图像超分自己的全局运行端和工作流**调用，强制 3 倍；只有超分成功后才保存到当前人物变体并选中。
- 面板不会在各处重写节点号：生成时从当前启用的 Qwen `TextEncodeQwenImage21` 向上追踪 `LoadImage` 和提示词节点，按 `ComfySwitchNode` 的实际连线选择 16:9 空潜变量分支、`ResolutionSelector=16:9`，只保留一张人物参考图。
- 四视图原图和超分结果都进入任务台账；最终资产只登记 3 倍超分版本。保存后刷新资产索引并选中该四视图新版本。相同图片内容已存在时沿用原版本，不重复堆版本。

### 人物音色

- 音色是**用户自主上传的可选人物文件**，登记为该人物资产里的 `role: voice`；不是第二个人物，也不是“参考音频”资产。
- 音色属于人物本身，必须放在身份变体，不能因为用户在礼服/家居服变体里点上传就变成两套音色。
- 人物卡片和人物详情都要提供“上传音色 / 替换音色”与试听；没有音色时保持原流程，不提示、不阻塞、不替用户生成音色。
- 短剧导演只引用用户已经上传的音色，不做音色合成、克隆、判断或改写。音色也不能被设为人物画面的当前输入；定妆照/四视图的封面与生成输入不受影响。

### H3 素材槽与提示词

- H3 里已经手写的 `<Picture N> 是 … 的参考。` 是用户原文，上传、替换或移除素材都不能改这一行。
- 上传到 `<Picture N>` 时，优先合并到同名的人物/场景/道具资产，并按文件用途登记为 `quadview`、`front` 或 `primary`；不要因为入口叫“参考图片”就另建同名副本。
- 素材栏的 `×` 只解除该槽位与当前文件的绑定：提示词保留，生成时该槽会被明确标为“素材已移除”并阻止误用；重新上传后恢复。

## 场景资产

- `task=text-to-image`，**16:9 横构图空镜**：画面中无人、无独立道具主体。提示词按 `drama-asset-prompts/references/场景提示词规范.md` 的六层结构写，首尾锚点按**项目画风**取对应那一套（真人 / 3D动漫 / 动画 三套都在该文件第二节，逐字复用）。**别默认套真人那套**：`ARRI Alexa 实拍 … 非三维渲染` 会把 3D 动漫 / 动画项目出成真人照片（实测整批返工）。
- 出图时先用 `comfy_graph` 找到当前启用工作流里的 `ResolutionSelector`，把画幅设成 `16:9`；不要背节点号。
- **一景多图**：夜晚、反打、改造前后等版本都归同一场景资产的变体，文件名写成 `旧仓库（夜）.png`、`旧仓库（反打）.png`；不要另立“夜版/日版”场景资产。夜版**必须用 `task=image-edit` 从原场景图编辑**，**只改第 3 层光源**；反打图同样必须从原场景图编辑并保持同一空间结构。禁止用 `task=text-to-image` 依据“夜景/反打”文字重新生成。
- 所有场景变体都保持 **16:9 横构图**，即使短剧成片是 9:16；不要生成竖屏场景图。
- 出图后用 `task=upscale-image` 超分 3 倍 → 存 `资产/场景资产/` → 在资产页展开该场景的变体核图 → `drama_workspace` `action=sync_asset`（`asset_kind=场景`）。

## 道具资产

- 第一次出现的道具用 `task=text-to-image`；已有道具的状态变体必须从原图走 `task=image-edit`，禁止重新文生图。画幅按形态选：**默认 1:1**；功能性多态并排（闭合/打开、正面/背面）、平面物件正背面、服装正背面都用 **16:9**。纯白底、主体四周留白（虚拟道具／特效概念走深色底，见道具规范）。
- 提示词按 `drama-asset-prompts/references/道具提示词规范.md` 写：正文直接从「纯白底道具单视角展示：」开始，**不带任何头部字段**，视角按形态分档；只写正向描述，不追加负面提示词或反向屏蔽词。
- **不超分**。带文字道具的文字必须逐字准确。
- 存 `资产/道具资产/` → `drama_workspace` `action=sync_asset`（`asset_kind=道具`）。

## 参数与并行

- 参数用户没指定就用工作流里的默认值；用户指定了按用户的（步数、cfg、种子、分辨率、放大倍数都能改）。
- 时长预期只能作粗略参考：一次人物链路（全局配置文生图 → 图片编辑四视图 → 3 倍图像超分）按几分钟到十几分钟估，实际取决于运行端和工作流。
- `comfy_run` 的 `timeout_ms` 默认 15 分钟；超时不会丢任务，用 `comfy_job` 带 `prompt_id` 继续取。

## 灵活服务

用户的需求只要模型能力范围内就尽量满足，不要用流程挡人。例如"一次性生成一个人物多种样貌再发给他选"——直接批量出多张让他挑，而不是让他逐张确认。用户对某张图不满意，先判断是**提示词**问题还是**参数**问题（画幅、步数、cfg、种子），改对的那一个再重出。
