# 换装与四视图

两条提示词在 `references/` 下，用法说明见 `references/换装与四视图_用法说明.md`（含实测尺寸链与验收标准）。换装和四视图都走全局配置里的**图片编辑**任务（`task=image-edit`）；云端 8888 与本地 8188 可以各自保存不同工作流，实际使用哪一份由全局配置的运行端决定，不要在调用里写死文件名。

提交层会自动把编辑提示词收成 Qwen Image 2.1 官方要求的一段式结构，并处理 `<imageN>` 引用、画幅字段和保真条款。手写提示词时只补画面要求，不要重复叠同样的前缀。

## 变体来源硬规则（不可跳过）

**换装是“编辑原人物”，不是“重新生成一个人”。** 必须把该人物基础形象或对应原变体的真实文件接到 `images.image_1`，再用图片编辑工作流换装；绝不能先走 `task=text-to-image` 生成服装参考图或新人物图。新服装的颜色、单品、材质和细节直接写进编辑提示词。

用户提供的服装参考图可以接到 `images.image_2` 作为辅助，但第一张人物原图才是身份唯一来源。没有原定妆照/原变体文件时停下来让用户确认，不能凭文字文生图后冒充变体。场景日夜、人物服装、年龄/受伤、道具状态都遵守同一条边界。

## 先读节点，再写节点号（重要）

**这份工作流被反复迭代保存过，节点号会随保存状态变。** 实测同一条工作流两次保存后：提示词节点从 `571 PrimitiveStringMultiline` 变成了 `517 PrimitiveStringMultiline`，而 `517` 还是被 **bypassed** 的那个。

所以铁律是：**每次动手前先 `comfy_graph`，用它返回的节点号**。`comfy_run` 现在会在 patch 没匹配上时报错并点名，看到这个报错就回去 `comfy_graph` 对一遍节点号。

工作流里三处提示词节点（`497 TextEncodeQwenImage21` 的 `prompt`、上游 `PrimitiveStringMultiline`、以及一个 bypassed 的备用组）**只有当前 active 的那一处算数**。`comfy_graph` 里显示 `<- node N` 的输入是被接线的，要改就去改上游那个节点。

## 跨机器槽位规则（执行前必做）

上面的 `497`、`475`、`505` 只是本机历史样例，**不是跨机器契约**。每次换机器、换工作流或用户改过组名后，都按下面步骤重新确认：

1. 设本次实际需要的不同图片文件数为 `N`。
2. 用 `comfy_graph` 找当前 active 的 `TextEncodeQwenImage21`，列出 `images.image_1...image_N`；每个槽位必须向上追到真实 `LoadImage`。
3. `skipped` 中或 `mode=4` / `mode=2` 的节点不可用。缺槽就启用对应 `LoadImage`、缩放链及所属组（`mode=0`）；槽位过多就旁路多余组（`mode=4`）。
4. 组标题在不同机器上可能不是 `image-K`。不要猜标题：从缺失的 `images.image_K` 反向找到它的上游节点，再启用包含这些节点的组。
5. ComfyUI 中可右键组标题设置组内节点，或用 `Fast Groups Bypasser` 批量切换；改完保存。
6. 重新 `comfy_graph`，确认编码器恰好只有 `images.image_1...image_N`，且没有旧图残留后才调用 `comfy_run`。

分镜管理的图像编辑表单和一键四视图会自动完成上述开关；**短剧导演直接调用 `comfy_run task=image-edit` 不会**。没有切组权限时必须停下来让用户开启/旁路并保存，不能把多出的参考图降级成文字。

## 踩过的两个坑（实测）

**坑一：`ComfySwitchNode` 两端分别是“参考图尺寸画布”和“指定比例画布”。**
当前这份整合工作流里，`on_false` 接 `497 TextEncodeQwenImage21.latent`（按第一张参考图尺寸建立画布），`on_true` 接 `479 EmptyLatentImage`（由 `ResolutionSelector` 决定目标比例）。同比例换装用参考图尺寸分支（当前为 `false`）；四视图必须从 9:16 定妆照生成 16:9，所以要走**指定比例分支**（当前为 `true`）。**不要凭记忆写 true/false**：先看两端各自接到哪里。面板和资产四视图生成会自动按目标画幅选择。

**坑二：`#487 SaveImage` 之外还有别的 SaveImage 节点，看状态别看名字。**
`512`/`513` 那类备用组的 `SaveImage` 是 bypassed 的；真正落盘的由当前 active 组决定。`comfy_graph` 的 `skipped` 列表会告诉你有多少节点被旁路。

**坑三：种子不写，出来的就是同一张图。**
同一条换装/四视图提示词连跑两次、结果**像素级相同**，不是模型稳定，是种子没写进去。本机这条流的种子在 `502.seed`（采样种子节点默认恒为 0）。**每次提交都显式给一个随机种子**，用户要复现才固定；换机器先 `comfy_graph` 找种子节点，看到 `<- node N` 就改上游（同一份图的"重跑一次"经验完全依赖它）。

## 换装 / 四视图的实测提示词节点对应

以本机当前保存状态为例（写死仅供对照，**用前必须重新 `comfy_graph`**）：

- 提示词节点 `571 PrimitiveStringMultiline`（`value`）
- 参考图 `475 LoadImage` → 经 `532 ImageScaleToTotalPixels` → `497.images.image_1`
- 尺寸 `13 ResolutionSelector`（`aspect_ratio` / `megapixels` / `multiple`）

`comfy_run` 里可以直接写 `"475.image": "定妆照.png"`（先上传）或 `"571.value": "<四视图提示词>"`；节点号不确定时可以用 `"*.value"` 表示"唯一声明该输入的那个节点"。

## 第一步 · 换装（9:16 进，9:16 出）

- 提示词正文：`references/换装.txt`，写进 **当前 active 的 `PrimitiveStringMultiline`**（它的文本经 link 进入 `497 TextEncodeQwenImage21` 的 `prompt`）。先用 `comfy_graph` 确认是哪一个。
- 原人物定妆照/原变体 → 当前 active 的 `images.image_1` 上游 `LoadImage`。默认只开 `image_1`；用户另外提供了已确认的服装参考图时，才把参考图接到 `images.image_2`。不要为了“换装”先让文生图造一张 image2。
- 若使用 `image_2`，先按上面的跨机器槽位规则启用对应组和缩放链，再 bind 文件；不使用时把多余槽位全部旁路。
- 当前 active 的 `ComfySwitchNode` = **false** → 输出尺寸跟着 image1 走，输入 9:16 就出 9:16。
- 提示词里**不能出现「四个视图」「四格」这类词**，否则模型会真的排成网格，还会把参考图里的人一起画进来。
- 换男角色时把提示词里的「女性」改成「男性」。
- **填空规则**：`把<image1>中人物穿着的【原服装】，整体替换为【新服装：颜色 + 单品 + 关键细节】。`
  - 【原服装】**必须写**，它是锁住人物身份的锚点；不写就会把参考图里的人一起搬进来（实测侧视图、背视图会直接换脸换发型）。
  - 【新服装】写「颜色 + 单品 + 关键细节」。只写「黑色西装套装」也能换，但鞋和内搭会自由发挥；只写「换成图二的服装」而不描述具体服装 → 输出基本等于原图，等于没换。没有 image2 时，绝不能省略新服装描述。

## 什么时候不做四视图（兽形 / 非人形 / 群体）

`四视图.txt` 是给**人形角色**写的：面部特写占 1/3、头身比、服装分区三条硬约束，句句假设有一张人脸和一套衣服。套到别的形象上，模型会**照着约束把人形部件长出来**——实测兽形角色被套成"人身兽头"，整张作废。

| 形象 | 出什么 | 不要做什么 |
|---|---|---|
| 人形角色（含换装变体） | 9:16 定妆照 → 16:9 四视图 → 3x 超分 | — |
| 兽形 / 灵体本体 / 器物拟人 / 机械 | **只出 9:16 定妆照** | 不套 `四视图.txt`；不把兽形结果当四视图登记 |
| 群体（`围观群众`、`记者若干`） | 16:9 群像 | 不做四视图、不拆成多个人物 |

需要多角度就**分别再生成一张**（例如正侧一张），不要用模板一次性排格。

## 第二步 · 四视图（9:16 进，16:9 出）

- 提示词正文：`references/四视图.txt`。
- 人物图 → 当前 active 的 `images.image_1` 上游 `LoadImage`，传第一步的输出图（重新上传/加载为 input 图）。
- **只保留 `images.image_1`**：`images.image_2...image_9` 不得出现在 active 编码器中；对应组全部旁路，避免参考图多于一张时模型去参考别的图。
- 当前 active 的 `ComfySwitchNode` = **true**，当前 active 的 `ResolutionSelector` = `16:9 (Widescreen)`；`megapixels` 设为 `1.5`。`multiple` 保持工作流当前值，不要跨机器照抄。
- 面部特写要「占三分之一以上」必须同时写三条硬约束：① 是整个画面里**最大的一格**；② 肩部横向**撑满该格**、肩线几乎触及左右边缘；③ 画面下缘**只到肩部下方一点**。只写百分比模型不会放大（实测 28.6% → 加硬约束后 36.8%）。这三条已经在 `四视图.txt` 里写好了，**不要删**。

## 落地要求

- 定妆照与四视图存到 `资产/人物资产/<角色名（身份）>/`，文件名用不带前缀的资产名（变体写 `角色名（造型）`）。
- 换装结果的主图就是该变体的定妆照。出图后必须先生成 16:9 四视图，再用全局配置的图像超分工作流超分 3 倍，登记到资产页当前变体，最后同步到各集 `本集所需资产/`。
- 尺寸链（可当验收标准）：`1080×1920` 定妆照 → `928×1664`（换装）→ `1664×928`（四视图）。四视图排版有随机性，偶尔回到 1/4 宽排版，重跑一次即可。
