# 换装 + 四视图 提示词用法（Qwen-Image-2.1 / ComfyUI）

配套文件：`换装.txt`（第一步）、`四视图.txt`（第二步）、`四视图_旧版备份.txt`（旧稿留档）。

## 用哪个工作流

使用全局配置里**图片编辑**任务（`task=image-edit`）当前选中的工作流。云端和本地可以不同；下面出现的文件名和节点号只是当前保存状态的示例，执行前必须用 `comfy_graph` 从实际生效的图里重新确认。

## 第一步 · 换装（9:16 进，9:16 出）

- 提示词写进当前启用的 `TextEncodeQwenImage21` 上游文本框（当前示例是 `571 PrimitiveStringMultiline`，经 link 843 进入 `497`）。写进旁路组里的备用文本框无效。
- 人物原定妆照或对应原变体接当前 active 的 `images.image_1` 上游 `LoadImage`。这是变体的唯一身份来源，**不能先用文生图生成一张“服装参考图”或“新人物图”**。`475` / `505` 只是本机旧例，不是跨机器节点号。
- 默认只开 `images.image_1`，新服装写在编辑指令里。用户另外提供了已确认的服装参考图时，才可以把它接到 `images.image_2`；其余参考组旁路。四视图只需要一张图：只保留 `images.image_1`，旁路和断开 `images.image_2...image_9`。组名被改过时，按槽位向上追踪到实际 `LoadImage`，不要按旧组名猜。
- `ComfySwitchNode(482)` = **false** → 输出尺寸跟着 image1 走，输入 9:16 就出 9:16。
- 提示词里**不能出现「四个视图」「四格」这类词**，否则模型会真的排成网格，还会把参考图里的人一起画进来。
- 换男角色时把「女性」改成「男性」。

## 第二步 · 四视图（9:16 进，16:9 出）

- `LoadImage(475)` = 第一步的输出图（重新上传/加载为 input 图）。
- **断开** `497` 的 `images.image_2`，只留一张参考图；参考图多于一张它会去参考别的图。
- 四视图要显式离开参考图的 9:16 画布：当前 active 的 `ComfySwitchNode` 选由 `ResolutionSelector` 控制的空潜变量分支，并设 `ResolutionSelector` = `16:9` + 1.5MP。同比例换装则选 `TextEncodeQwenImage21` 的参考图尺寸分支。相关节点号每次用 `comfy_graph` 重新读取。
- 面部特写要「占三分之一以上」，必须同时写三条硬约束：
  1. 是整个画面里**最大的一格**；
  2. 肩部横向**撑满该格**、肩线几乎触及左右边缘；
  3. 画面下缘**只到肩部下方一点**。
  只写百分比（「占三分之一」）模型不会放大：实测 28.6% vs 加硬约束后 36.8%。

## 换装提示词的两处填空规则

`把<image1>中人物穿着的【原服装】，整体替换为【新服装：颜色 + 单品 + 关键细节】。`

- 【原服装】**必须写**，它是锁住人物身份的锚点。不写就会把参考图里的人一起搬进来（实测：侧视图、背视图直接换脸换发型）。
- 【新服装】写「颜色 + 单品 + 关键细节」。只写「黑色西装套装」也能换，但鞋和内搭会自由发挥。
- 只写「换成图二的服装」而不描述具体服装 → 输出基本等于原图，等于没换。
- 如果确实上传了第二张已确认的服装参考图，可以补充“同时参考 `<image2>` 的服装款式”；不能因此省掉新服装描述，也不能把 `<image2>` 说成人物身份来源。

## 实测数据（可当验收标准）

- 尺寸链：`1080×1920` 定妆照 → `928×1664`（换装）→ `1664×928`（四视图）。
- 四视图排版：特写格宽 ≈ 0.36，其余三格各 ≈ 0.13。
- 单步耗时约 20 秒（int8 + 加速节点）。
- 四视图排版有随机性，偶尔回到 1/4 宽排版，重跑一次即可。
